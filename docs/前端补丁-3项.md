## ① 账本混币显示【P0，建议必做】

### 问题现象

记了多个币种的账目时，**「记账」页只显示其中一个币种那一组，另一个币种整组消失**，而且金额单位标签是写死的 `CNY`。

用户记了 1000 CNY 收入 + 200 USD 收入，页面上只看得到 1000，那 200 USD 像是没记上。

### 根因

`web/app.js` **第 1419–1422 行**，三张卡的单位写死：

```js
  const data = await api(`/api/ledger?productId=${state.current.id}`);
  const s = data.summary;
  $('#summary').innerHTML = `
    <div class="stat"><div class="stat-label">收入</div><div class="stat-value">${money(s.income)}<span class="stat-unit">CNY</span></div></div>
    <div class="stat"><div class="stat-label">成本</div><div class="stat-value cost">${money(s.cost)}<span class="stat-unit">CNY</span></div></div>
    <div class="stat"><div class="stat-label">利润</div><div class="stat-value">${money(s.profit)}<span class="stat-unit">CNY</span></div></div>`;
```

`s.income / s.cost / s.profit` 是后端为了**向后兼容**保留的顶层字段，取的是"条目最多的那个币种"那一组。
换句话说：**数字本身没算错，但它只代表一个币种**，而页面给它贴了固定的 `CNY` 标签。

### 后端实际返回（实测，非推测）

请求 `GET /api/ledger?productId=xxx`，当存在多币种时：

```json
{
  "summary": {
    "income": 1000, "cost": 300, "profit": 700, "currency": "CNY",
    "byCurrency": [
      { "currency": "CNY", "count": 2, "income": 1000, "cost": 300, "profit": 700 },
      { "currency": "USD", "count": 1, "income": 200, "cost": 0,   "profit": 200 }
    ],
    "mixed": true
  }
}
```

- `byCurrency`：按币种分好的数组，条目多的排前面。**新代码读这个。**
- `currency`：顶层数字对应的币种（这里是 `CNY`），**别再写死了，用它**。
- `mixed`：`true` 表示存在多币种。单币种时为 `false`，`byCurrency` 只有一项。

### 改法

把第 1419–1422 行整段替换为：

```js
  const data = await api(`/api/ledger?productId=${state.current.id}`);
  const s = data.summary;
  // 后端按币种分好组；单币种时 byCurrency 只有一项，行为与改造前一致
  const groups = (s.byCurrency && s.byCurrency.length) ? s.byCurrency : [
    { currency: s.currency || 'CNY', income: s.income, cost: s.cost, profit: s.profit },
  ];
  $('#summary').innerHTML = groups.map((g) => `
    <div class="stat"><div class="stat-label">收入${groups.length > 1 ? ` · ${esc(g.currency)}` : ''}</div><div class="stat-value">${money(g.income)}<span class="stat-unit">${esc(g.currency)}</span></div></div>
    <div class="stat"><div class="stat-label">成本${groups.length > 1 ? ` · ${esc(g.currency)}` : ''}</div><div class="stat-value cost">${money(g.cost)}<span class="stat-unit">${esc(g.currency)}</span></div></div>
    <div class="stat"><div class="stat-label">利润${groups.length > 1 ? ` · ${esc(g.currency)}` : ''}</div><div class="stat-value">${money(g.profit)}<span class="stat-unit">${esc(g.currency)}</span></div></div>`).join('');
```

**说明**

- 单币种时渲染结果与改造前**完全一致**（3 张卡，标签不带币种后缀），不会影响现有演示。
- 多币种时每个币种渲染 3 张卡，标签变成「收入 · CNY」「收入 · USD」加以区分。
- `esc()` 是文件里已有的转义函数，直接复用。
- `money()` 是该函数内已定义的局部函数（第 1408 行），位置不变可直接用。

### 如果不想改布局（更保守的最小改法）

只修"写死 CNY"这一点，再加一行提示，不动卡片结构：

```js
  const data = await api(`/api/ledger?productId=${state.current.id}`);
  const s = data.summary;
  const cur = esc(s.currency || 'CNY');
  const others = (s.byCurrency || []).slice(1);
  $('#summary').innerHTML = `
    <div class="stat"><div class="stat-label">收入</div><div class="stat-value">${money(s.income)}<span class="stat-unit">${cur}</span></div></div>
    <div class="stat"><div class="stat-label">成本</div><div class="stat-value cost">${money(s.cost)}<span class="stat-unit">${cur}</span></div></div>
    <div class="stat"><div class="stat-label">利润</div><div class="stat-value">${money(s.profit)}<span class="stat-unit">${cur}</span></div></div>
    ${s.mixed ? `<p class="muted-sm">另有 ${others.map((g) => `${esc(g.currency)} ${g.count} 笔`).join('、')} 未计入上方（不同币种不混算）</p>` : ''}`;
```

这个版本改动更小，但至少**不会再隐瞒另一个币种的存在**。两个版本任选其一。

## ② 进度条显示 `job.stage`【P1，10 分钟】

### 问题现象

出图/出详情页时，进度条旁边显示的是英文状态词：

```
73% · running
```

用户不知道 `running` 是什么意思，也不知道 3 张图出到第几张了。

### 根因

`web/app.js` 有 **6 处**把 `job.status`（英文枚举）直接当成展示文案传给了进度条：

| 行号 | 当前写法 |
|------|----------|
| 1130 | `jobPromise(jobId, (job) => box.update(job.progress \|\| 0, job.status))` |
| 1193 | 同上 |
| 1219 | 同上 |
| 1287 | 同上 |
| 1336 | 同上 |
| 1384 | 同上 |

另有 2 处传的是写死的中文（这两处可改可不改）：

| 行号 | 当前写法 |
|------|----------|
| 1020 | `prog.update(job.progress \|\| 0, '分析中')` |
| 1061 | `prog.update(job.progress \|\| 0, '精修锁形')` |

### 好消息：展示逻辑已经就绪

`progressBubble()` 的 **第 758 行**早就支持第二个参数了：

```js
    if (label) label.textContent = Math.round(cur) + '%' + (tag ? ' · ' + tag : '');
```

所以**只要换掉传进去的值就行**，不用动 `progressBubble` 本身。

### 后端实际返回（实测）

`GET /api/jobs/:id` 现在会带 `stage` 字段：

```json
{ "status": "running", "progress": 45, "stage": "已完成 2/3 张" }
```

- 出图链路：`"参考图已锁定，开始出图（共 3 张）"` → `"已完成 1/3 张"` → `"已完成 2/3 张"` …
- 其他链路：`"已排到，开始处理"` → `"完成"`
- **任务刚建还没被调度时 `stage` 是 `null`**，所以必须留兜底。

### 改法

把那 6 处的 `job.status` 换成 `job.stage || job.status`：

```js
// before
jobPromise(jobId, (job) => box.update(job.progress || 0, job.status))

// after
jobPromise(jobId, (job) => box.update(job.progress || 0, job.stage || job.status))
```

**可选增强**：1020、1061 两处的写死文案也可以让位给真实阶段：

```js
// before
jobPromise(jobId, (job) => prog.update(job.progress || 0, '分析中'))
// after
jobPromise(jobId, (job) => prog.update(job.progress || 0, job.stage || '分析中'))
```

**整个改动就是加 `job.stage || ` 这 11 个字符 × 6（或 8）处。**

### 为什么值得做

真实模式下出 3 张图要约 56 秒。改之前用户盯着「45% · running」不知道发生了什么；
改之后是「45% · 已完成 1/3 张」，等待焦虑完全不同。

### 自验

```bash
node server.mjs
# 「生图」页发一张图 → 走到出图步骤，看进度条文案
```

mock 模式太快可能一闪而过，可以临时放慢观察：

```bash
# Windows PowerShell
$env:JOB_CONCURRENCY=1; node server.mjs
```

或直接在浏览器 Network 里看 `/api/jobs/<id>` 的响应，确认 `stage` 字段有值。

## ③ 限流 429 友好提示【P2，20 分钟】

### 问题现象

连续快速点击出图按钮，或局域网演示时多人同时操作，会弹出一句红字：

```
请求过于频繁（每分钟上限 20 次），请 47 秒后再试
```

文案本身还行，但：**前端不知道这是限流**，所以当成普通失败处理——不会禁用按钮、不会倒计时、不会自动恢复，用户只能反复试。

### 根因

`web/app.js` **第 38–47 行**的 `api()` 把所有错误压成一个纯字符串，`code` 和 `Retry-After` 全部丢弃：

```js
async function api(path, { method = 'GET', body, headers } = {}) {
  const res = await fetch(path, {
    method,
    headers: body ? { 'content-type': 'application/json', ...headers } : headers,
    body: body ? JSON.stringify(body) : undefined,
  });
  const data = await res.json().catch(() => ({}));
  if (!res.ok) throw new Error(data?.error?.message || `HTTP ${res.status}`);   // ← 信息在这里丢光
  return data;
}
```

下游所有 `catch (e)` 只拿得到 `e.message`，没法区分"被限流了"和"参数写错了"和"模型挂了"。

### 后端实际返回（实测）

```
HTTP 429
Retry-After: 60
{"error":{"code":"RATE_LIMITED","message":"请求过于频繁（每分钟上限 3 次），请 60 秒后再试"}}
```

> 注：本机回环地址（localhost）**默认豁免限流**，所以本地自测通常不会触发。
> 要复现，启动时加 `RL_LOCALHOST=strict`，并调小阈值如 `RL_JOBS_PER_MIN=3`。

### 改法（两步）

**第一步**：让 `api()` 把结构化信息带出来。替换第 38–47 行：

```js
async function api(path, { method = 'GET', body, headers } = {}) {
  const res = await fetch(path, {
    method,
    headers: body ? { 'content-type': 'application/json', ...headers } : headers,
    body: body ? JSON.stringify(body) : undefined,
  });
  const data = await res.json().catch(() => ({}));
  if (!res.ok) {
    const err = new Error(data?.error?.message || `HTTP ${res.status}`);
    // 把结构化信息挂到 error 上，下游想用就用，不用也不影响（e.message 行为不变）
    err.code = data?.error?.code || 'HTTP_ERROR';
    err.status = res.status;
    err.retryAfter = Number(res.headers.get('retry-after')) || 0;
    throw err;
  }
  return data;
}
```

**这一步是向后兼容的**：现有所有 `catch (e) { ...e.message... }` 行为完全不变，只是多了几个可选属性。

**第二步**：在想要友好提示的地方识别它。推荐先只改出图这一条主路径（第 1132 行附近的 `catch`）：

```js
  } catch (e) {
    box.done();
    if (e.code === 'RATE_LIMITED') {
      say(inner, 'ai', `<p class="err">操作太频繁了，${e.retryAfter || 60} 秒后再试。<br><span class="muted-sm">这是为了避免误触烧掉出图额度。</span></p>`);
    } else {
      say(inner, 'ai', `<p class="err">出图失败：${esc(e.message)}</p>`);
    }
    return;
  }
```

**可选增强**：限流时顺便把发送按钮禁用并倒计时：

```js
if (e.code === 'RATE_LIMITED') {
  const btn = $('#btnSend');
  let left = e.retryAfter || 60;
  btn.disabled = true;
  const original = btn.textContent;
  const t = setInterval(() => {
    btn.textContent = `${left--} 秒后可重试`;
    if (left < 0) { clearInterval(t); btn.disabled = false; btn.textContent = original; }
  }, 1000);
}
```

### 自验

```bash
# 开启本机限流，阈值调到 3
# Windows PowerShell:
$env:RL_LOCALHOST="strict"; $env:RL_JOBS_PER_MIN="3"; node server.mjs
```

然后在「生图」页连点 4 次出图，第 4 次应看到友好提示而不是普通红字报错。
测完去掉这两个环境变量即可恢复默认（本机豁免）。

## 附：后端已就绪、但本次不建议做的

这些后端都已支持，前端什么时候想用什么时候接，**不着急**：

| 能力 | 后端字段/接口 | 前端接了能做什么 |
|------|---------------|------------------|
| 任务列表 | `GET /api/jobs?productId=&status=` | 刷新页面后恢复未完成任务的进度条（现在刷新就失联） |
| 取消任务 | `DELETE /api/jobs/:id` | 进度条旁加「取消」按钮，发错了不用干等 50–70 秒 |
| 当日用量 | `GET /api/meta` 的 `usage` | 「接口」页显示：今日已出 X 张 / 预估 ¥Y / 上限 Z |
| 原始文件名 | `asset.meta.originalName` | 仓库卡片显示「实拍-45度.png」而不是「a_2f4e01.png」 |
| 视频拖进度条 | `/files/*` 已支持 Range/206 | 视频面板加 `<video>` 播放器即可拖动 |
| 分页 | `GET /api/products` 的 `nextCursor` | 商品超过 50 个后才需要 |
